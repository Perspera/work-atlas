## 一、先看清拓扑（别改错端口）

```
外部浏览器 ──TCP 18081──> 云安全组(入方向) ──> ECS 8.163.57.96
                                            └─> nginx :18081  (deploy/nginx-work-atlas.conf:9)
                                                  ├─ allow 127.0.0.1 / ::1 / 183.233.190.250
                                                  ├─ deny all
                                                  └─ proxy_pass http://127.0.0.1:18082
                                                       └─ 应用 server.py（prod profile: bind 127.0.0.1, port 18082）
```

| 端口 | 谁监听 | 对外可见 | 本次是否动 |
|---|---|---|---|
| **18081** | nginx | **是**（云安全组入方向管的就是它） | ✅ **只动它** |
| 18082 | 应用 server.py | 否（只绑 127.0.0.1） | ❌ 不动，安全组里不应有它的放行规则 |
| 22 | sshd | 是（部署/回滚用） | ❌ **千万不要动**，否则部署与回滚都断 |

依据：`deploy/deploy.ps1:20` `[int]$Port = 18082`、`:97` 健康检查打 `http://127.0.0.1:18082/api/health`、`:153` 打印 `http://8.163.57.96:18081`；`deploy/nginx-work-atlas.conf:9-20` `listen 18081` / `proxy_pass http://127.0.0.1:18082`；`config.json:12-19` prod profile `port 18082, bind 127.0.0.1`。**18081 是唯一的公网入口，18082 从不出主机。**

> 存在**两层白名单**：① 云安全组（网络层，DROP/放行）；② nginx `allow/deny`（应用层，返回 403）。两层都要收紧才完整，但本次用户要做的 D 组仅指第 ① 层；第 ② 层 `deploy/nginx-work-atlas.conf:16` 已经写死 `allow 183.233.190.250; deny all;`，上线时会随包生效。清单第 6 步给出两层一致性核对方法。

## 二、执行前必做的 3 项确认（重要，避免把自己锁在外面）

1. **确认办公网出口 IP 仍是 `183.233.190.250`**
   在**办公网内**的电脑浏览器访问任意查 IP 站点（如 `https://myip.ipip.net`、`https://ip.sb`），核对显示的公网 IPv4。
   - 若 ≠ `183.233.190.250`：**先不要收紧**。真实出口 IP 变了，收紧后全公司立刻访问不了。需同步改两个地方再执行：云安全组授权对象 + `deploy/nginx-work-atlas.conf:16` 的 `allow` 行（改完 `nginx -t && systemctl reload nginx`）。
   - 若公司有多个出口 / 有备用线路：把每个出口 IP 都作为 `/32` 逐条加进授权对象，或用一个能覆盖的 CIDR。

2. **确认 ``183.233.190.250/32`` 是 IPv4 单 IP**
   阿里云「授权对象」填 `183.233.190.250/32`（**必须带 `/32`**；只填 IP 不带掩码会被当成别的含义或校验失败）。不要填成 `183.233.190.250/24`。

3. **确认有独立于 18081 的兜底通道**
   - 阿里云控制台本身是控制面，**不受该实例安全组影响**，随时能进去改回来（这就是回滚通道）。
   - 另外确认 SSH(22) 对你当前 IP 是放行的：`deploy/deploy.ps1` 上线和 P4 C 组回滚命令都要用 `ssh root@8.163.57.96`。

## 三、收紧步骤（阿里云 ECS 控制台）

> 控制台文案会随版本微调，按语义找对应项即可。全程**保存即生效，无需重启实例、无需重启 nginx**。

**第 1 步** 登录 [阿里云 ECS 控制台](https://ecs.console.aliyun.com/) → 左侧「实例与镜像 / 实例」→ 地域选该实例所在地域 → 找到 `8.163.57.96` 对应实例 → 点实例 ID 进详情。

**第 2 步** 详情页切到「**安全组**」页签 → 记下绑定的安全组名称/ID → 点安全组 ID → 「**配置规则**」（或「管理规则」）。

**第 3 步** 切到「**入方向**」→「手动添加 / 已有规则列表」。先**定位**这条待改规则：

| 字段 | 目标值 |
|---|---|
| 方向 | 入方向 |
| 授权策略 | 允许 |
| 协议类型 | 自定义 TCP（或 TCP） |
| 端口范围 | `18081/18081`（若写成 `18081/18082` 或更大范围，见第 5 步「顺带检查」） |
| 授权对象（源） | **`0.0.0.0/0`** ← 这就是要改的 |
| 优先级 | 保持原值（通常 1） |

**第 4 步** 点该规则「**编辑 / 修改**」，只改一个字段：

```
授权对象（源）：0.0.0.0/0   →   183.233.190.250/32
```

其余字段（协议、端口、优先级、描述）**一律不动**。建议把「描述」补成 `公司办公网出口-看板入口`，便于以后核对。点「保存 / 确定」。

**第 5 步 · 顺带检查（别漏）**
- 检查入方向是否**还有别的**放行 `18081` 的规则（例如另一条 `0.0.0.0/0`、或端口范围 `18080/18090` 把 18081 一起放开、或 IPv6 `::/0`）。若有，一并改成 `183.233.190.250/32` 或删除/停用——**只要还留一条全放行规则，收紧就无效**。
- 检查入方向**不要**新增或放行 `18082`（应用只绑环回，不该对外）。
- 确认 `22`（SSH）规则仍在，别误删。

**第 6 步 · 两层一致性核对（可选但推荐）**
SSH 到实例确认 nginx 白名单与云安全组是同一个 IP：

```bash
ssh root@8.163.57.96 "grep -n 'allow\|deny\|listen' /etc/nginx/conf.d/work-atlas.conf"
# 期望看到：listen 18081;  allow 183.233.190.250;  deny all;
# 若不一致，改完执行：nginx -t && systemctl reload nginx
```

若 nginx 那层还是旧的/没装，本次只做云安全组即可，但要在上线时确认 `deploy/nginx-work-atlas.conf` 随包生效。

## 四、验证（收紧后立刻做，正反两面都测）

**A. 允许侧（办公网内，应能访问）**
```
浏览器打开 http://8.163.57.96:18081   → 应出现登录页（200）
命令行：curl -I http://8.163.57.96:18081/api/health   → HTTP 200 {"ok":true,...}
```
> `/api/health` 是公开接口（`server.py:292-294`），不用登录，最适合做连通性探针。

**B. 拒绝侧（非办公网，应访问不了）**
用**手机关掉 WiFi、走蜂窝网络**（或任意非 `183.233.190.250` 的来源）访问 `http://8.163.57.96:18081`：
- 云安全组已生效 → **连接超时 / 无法建立连接**（网络层直接丢包，这是本次 D 组想要的效果）。
- 若看到 **nginx 403 Forbidden** 而不是超时，说明云安全组还有全放行规则没清干净（回第 5 步），只是 nginx 那层在挡。

**C. 部署通道仍通**
```
ssh -o BatchMode=yes root@8.163.57.96 "echo SSH_OK"
```
必须成功，否则上线与回滚会断。

| 检查 | 期望 | 实际 |
|---|---|---|
| 办公网 18081 | 200 / 登录页 | □ |
| 非办公网 18081 | 超时（非 403） | □ |
| SSH 22 | 成功 | □ |
| 18082 对外 | 不通 | □ |

## 五、回滚方式

### 5.1 立刻回滚到原状（最常用）
阿里云控制台 → 同一安全组 → 入方向 → 找到刚改的那条规则 → 「编辑」→ 授权对象改回：

```
183.233.190.250/32   →   0.0.0.0/0
```

保存即生效（秒级，无需重启）。**控制台是控制面，即使把自己锁在 18081 外面也能登进去改**，所以不会被彻底锁死。

### 5.2 只是「新 IP 访问不了」而不是要全放开
不要改回 `/0`，而是在入方向**新增**一条同端口规则：

| 字段 | 值 |
|---|---|
| 协议类型 | 自定义 TCP |
| 端口范围 | `18081/18081` |
| 授权对象 | `<新出口IP>/32` |
| 授权策略 | 允许 |
| 优先级 | 1（与现有相同即可） |

同时同步 `deploy/nginx-work-atlas.conf` 的 `allow` 行并 `nginx -t && systemctl reload nginx`（否则云层放行了、nginx 仍 403）。

### 5.3 若 nginx 那层也误改坏了
```bash
ssh root@8.163.57.96
# 编辑 /etc/nginx/conf.d/work-atlas.conf，恢复：
#   allow 127.0.0.1; allow ::1; allow 183.233.190.250; deny all;
nginx -t && systemctl reload nginx
```
部署包内始终有 `deploy/nginx-work-atlas.conf` 可作参考原件。

### 5.4 什么情况下必须回滚
- 公司出口 IP 变了、新 IP 没提前加 → 全公司 18081 超时 → 按 5.1 或 5.2。
- 上线 `deploy/deploy.ps1` 时 `scp`/`ssh` 走不通 → 先确认 22 规则，再考虑临时放宽。
- 线上回归需要从外部网络（非办公网）访问 → 临时按 5.1 放开，回归完再收紧。
